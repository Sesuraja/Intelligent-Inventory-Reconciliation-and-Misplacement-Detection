# Fixed UHF RFID Hardware Integration Guide

## 1. Supported Hardware & Protocols

The system interfaces with 4-port fixed UHF RFID readers supporting the EPCglobal LLRP standard:

- **Impinj Speedway R420** (4 Antenna Ports, LLRP on TCP `5084`)
- **Zebra FX9600 / FX7500** (4/8 Ports, LLRP on TCP `5084`)
- **Alien ALR-F800** (4 Ports, LLRP / Alien Protocol)
- **ThingMagic Sargas / Astra-EX** (LLRP / MercuryAPI)

---

## 2. LLRP Communication Architecture

```
+--------------------------------------------------------------------------+
|  Host Application (FastAPI / LLRPReaderAdapter)                         |
|  - IP: 192.168.1.50                                                     |
+--------------------------------------------------------------------------+
                                  |
                                  | TCP Connection (Default Port: 5084)
                                  v
+--------------------------------------------------------------------------+
|  Fixed UHF Reader (e.g., Impinj Speedway R420)                          |
|  - Default IP: 192.168.1.100                                            |
|                                                                          |
|  [Port 1: Shelf A]   [Port 2: Shelf B]   [Port 3: Shelf C]   [Port 4: Shelf D] |
+--------------------------------------------------------------------------+
```

### Connection Handshake Sequence

1. **TCP Connection:** Host initiates TCP connection to `RFID_READER_HOST:RFID_READER_PORT`.
2. **Reader Event:** Reader responds with `READER_EVENT_NOTIFICATION` (ConnectionAttemptEvent).
3. **Capability Discovery:** Host dispatches `GET_READER_CAPABILITIES` (Message Type 1). Reader returns antenna port count and transmitter power limits in `GET_READER_CAPABILITIES_RESPONSE` (Type 11).
4. **ROSpec Definition:** Host builds `ADD_ROSPEC` (Type 20) with:
   - Antenna inventory parameter specs for active ports (1 through 4)
   - Transmit power (e.g. 30 dBm)
   - Report triggers (immediate tag report delivery)
5. **ROSpec Activation:** Host dispatches `ENABLE_ROSPEC` (Type 24) followed by `START_ROSPEC` (Type 22).
6. **Tag Data Streaming:** Reader continuously streams `RO_ACCESS_REPORT` (Type 61) frames containing EPC-96 identifiers, antenna IDs, peak RSSI, and UTC timestamps.
7. **Keepalive Heartbeat:** Reader periodically sends `KEEPALIVE` (Type 62); host acknowledges with `KEEPALIVE_ACK` (Type 72).

## 3. Operating Modes & Switching

The system provides three operational telemetry modes:

### `SIMULATION` (Default for Development / Testing)
- Telemetry generated by `UHFHardwareSimulator`.
- Accurately models Friis path loss, multi-shelf antenna cross-reading, RF shadowing from metal/liquid, and reader outages.
- Every observation is recorded with `source = 'SIMULATION'`.

### `PHYSICAL` (Live Warehouse Deployment)
- Connects directly to hardware reader over TCP `5084` via `LLRPReaderAdapter`.
- Receives real physical Gen2 backscatter tag reads.
- Every observation is recorded with `source = 'PHYSICAL'`.
- If the hardware reader is unreachable, the system reports status `OFFLINE` and **never claims false connectivity**.

### `OFFLINE` (Standby)
- Data collection is paused.
- No simulated or physical reads are accepted.

### How to Switch Modes
Via REST API:
```bash
curl -X POST http://localhost:8000/api/v1/system/mode \
  -H "Content-Type: application/json" \
  -d '{"mode": "PHYSICAL"}'
```
Or via the interactive **Operating Mode Pill** in the top navigation header.

## 4. Hardware Verification & Socket Probe

To verify reader connectivity without risking application crash:
```bash
curl -X POST http://localhost:8000/api/v1/readers/1/test-connection
```
Response when physical reader is connected:
```json
{
  "success": true,
  "reader_code": "READER_01",
  "operating_mode": "PHYSICAL",
  "physical_reachable": true,
  "latency_ms": 2.4,
  "ip_address": "192.168.1.100",
  "port": 5084,
  "protocol": "LLRP",
  "message": "Physical reader READER_01 responded in 2.4ms"
}
```
Response when physical reader is offline:
```json
{
  "success": false,
  "reader_code": "READER_01",
  "operating_mode": "SIMULATION",
  "physical_reachable": false,
  "latency_ms": 3002.1,
  "ip_address": "192.168.1.100",
  "port": 5084,
  "protocol": "LLRP",
  "message": "Physical reader READER_01 at 192.168.1.100:5084 is unreachable over TCP. Active operating mode is SIMULATION."
}
```
